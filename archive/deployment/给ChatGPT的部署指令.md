### 第 2 步：添加 DNS 解析（改之前先问我）
1. 打开 DNSPod 控制台：https://console.dnspod.cn/ ，进入域名 `noiamist.com` 的解析记录列表。
2. 检查是否已经存在主机记录 `soochowhackathon261101`。**如果已经存在，停下来问我。**
3. 向我确认后，添加一条记录：

   - 记录值：第 1 步拿到的服务器公网 IP

### 第 3 步：确认防火墙放行 80 和 443（改之前先问我）

检查 TCP 80 和 TCP 443 是否已允许所有来源（0.0.0.0/0）访问。已经放行就跳过；没有放行的话，告诉我要添加哪两条规则，等我确认后再添加。不要删除或修改已有的规则。

### 第 4 步：打开服务器网页终端

### 第 5 步：上传部署包
1. 用 OrcaTerm 的「文件上传」功能，在 Mac 的文件选择窗口中选择：
   `<workspace>/部署包/brand-assistant.tar.gz`

3. 运行 `ls -la ~/brand-assistant.tar.gz`，确认文件存在，大小约 120 KB。

### 第 6 步：解压
在终端里逐条运行：

```bash

sudo tar -xzf ~/brand-assistant.tar.gz -C /opt/brand-assistant
cd /opt/brand-assistant && ls
sudo cp -n .env.example .env.local
```

## 常见情况的处理（先告诉我，得到同意后再执行）

| 现象 | 处理方式 |
|---|---|
| 脚本提示“端口 3100 已被其他程序占用” | 改用别的端口：`cd /opt/brand-assistant && sudo PORT=3200 bash deploy/setup.sh` |
| 脚本提示“域名还没有解析到本服务器” | DNS 生效需要几分钟。等 5–10 分钟后重新运行第 8 步的命令 |
| 证书申请失败 | 检查第 3 步的 80 / 443 是否已放行，然后重新运行第 8 步 |
| 构建时出现 `Killed` 或内存不足 | 服务器内存太小。经我同意后添加 2G 交换空间，再重新运行第 8 步：`sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile` |
| 页面显示「离线预设结果」 | 可能是 key 没填对。告诉我，由我检查 `.env.local`，然后运行 `pm2 restart brand-assistant` |
| 安装 Node.js 或依赖时下载失败 | 把完整报错告诉我，不要自行更换下载源 |
